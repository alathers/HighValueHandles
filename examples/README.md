# Examples

## `processed_sample/`: one bottle as `bourbon-process` writes it

`processed_sample/example_creek_single_barrel/` is the output folder of one
fictional bottle, "Example Creek Single Barrel". It is generated by
[`scripts/regen_example_sample.py`](../scripts/regen_example_sample.py) with
the real output code (hint overrides, the enrichment phase, the fact checker
and `PreviewGenerator.save_bottle_files`). The search results and the text
model's replies are scripted, so no model and no network are used. The photo
is a small synthetic placeholder, and photo paths read `/path/to/photos`.

```
processed_sample/
└── example_creek_single_barrel/
    ├── .bourbon_output                       # marks the folder as output (later scans skip it)
    ├── example_creek_single_barrel.md        # Markdown page
    ├── example_creek_single_barrel.json      # full record, schema_version 2
    ├── example_creek_single_barrel.txt       # OCR text, then "web: 4 pages consulted, 1 cited"
    ├── evidence/
    │   ├── W1.txt                            # web excerpt the fact check read (official page)
    │   └── W2.txt                            # web excerpt (retailer page)
    └── images/
        └── IMG_0001.jpg                      # copy of the source photo
```

With `-v`, an accepted vendor photo would also appear as
`images/vendor_ref.<ext>` (reference only, not licensed for publication).

What the sample shows:

- **Supported from the label and OCR**: proof 100 is read from the label and
  backed by the OCR line "100 PROOF" (confidence high). The model's web
  claim for the proof was rejected by the verifier (`release_not_near_quote`:
  the page does not name this batch), and the rejection is kept in
  `facts.verification.rejected`.
- **Verified on the web**: the distillery is backed by the label, the OCR text
  and a quote from the official page W1.
- **MSRP Unknown with a reason**: the label shows $64.99 and a shop page
  $69.99; both are recorded as retail prices, and no source stated an MSRP.
- **A resolved conflict**: the label reads batch "C92"; the hints file says
  "C923" with its source, so the person's value wins and both values are
  kept under Needs Review.
- **The Web Research Log**: two fetched pages (one cited, one not cited and
  why) and two skipped pages (deny-listed, robots.txt).
- **The publish gate**: not publish-ready, because no one has approved it.

Regenerate it after changing the output code (a contract test,
`tests/contract/test_example_sample.py`, fails when the sample is stale):

```bash
uv run python scripts/regen_example_sample.py
```

## `hints.example.toml`: a hints file

Reading notes and sourced field values per bottle, for `--hints PATH` (or
`processing.hints_file` in `bourbon.toml`). See
[README.md#hints](../README.md#hints).

## Producing real output

```bash
# Check settings, photos, Tesseract, Ollama and the models first
uv run bourbon-process process -f /path/to/bottle/photos --dry-run

# Process a folder (output goes to processed/)
uv run bourbon-process process -f /path/to/bottle/photos

# Choose the output folder, use hints, review every bottle
uv run bourbon-process process -f /path/to/bottle/photos -o /custom/output \
    --hints examples/hints.example.toml --interactive

# Approve a bottle afterwards
uv run bourbon-process feedback -o /custom/output --approve IMG_0001
```

The bottle JSON is meant to be read by other tools (a website, a database, a
social media workflow). Use only bottles whose `facts.publish.ready` is
`true`, and cite the sources listed in `facts.sources` and
`reference_links`.
